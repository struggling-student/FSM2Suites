\section{Verification and Validation}

\subsection{Unit Tests}

The generator project contains an extensive suite of unit tests located in
\texttt{generator/tests/}. Tests exercise individual
modules such as the model classes, rule engine, parsing utilities and test
strategies.  Model tests validate the behaviour of \texttt{Variable},
\texttt{State}, \texttt{Action} and \texttt{Machine} objects. They ensure that
states correctly track actions, variable mappings are applied, and rule checking
works across different assignments.  Rule tests cover the diverse set of
condition types provided by the library, including equality, inequality,
comparison and regular expression operators.  Composite logic such as AND, OR,
NOT and implication is also checked for correct evaluation.

The parsing module is verified dedicated tests. These construct small
machine definitions in the Robot Framework style and feed them to the
\texttt{parse} function. Parsing handles variables, settings, user-defined
keywords and rule declarations. The following snippet from
\texttt{test\_parsing.py} illustrates how conditional actions and rules are
validated:
\begin{lstlisting}[language=python]
machine_text = """*** Machine ***
${VAR1}  any of  a  b
${VAR2}  any of  1  2

${VAR1} == a  ==>  ${VAR2} == 1

Start
  [Actions]
    action1  ==>  End

End
"""
machine = parse(machine_text)
self.assertEqual(len(machine.rules), 1)
self.assertTrue(machine.rules_are_ok(["a", "1"]))
self.assertFalse(machine.rules_are_ok(["a", "2"]))
\end{lstlisting}
Each test confirms that the parser not only instantiates the machine correctly
but also evaluates the resulting rules as expected.

Generation strategies are checked in isolation via tests. The
\texttt{DepthFirstSearchStrategy} is validated for deterministic path
exploration, action limits and optional target states. The
\texttt{RandomStrategy} is stressed with repeated value generation and random
walks to ensure variability.  Generator unit tests focus on producing Robot
Framework output. They confirm coverage tracking, limit handling and elimination
of duplicate tests.  Together, these unit tests guard each component against
regressions and provide confidence that the smaller building blocks behave as
specified.

Several tests purposefully target boundary scenarios. Examples include empty
machines with no actions, invalid state names and variable identifiers that do
not match the required regular expression. These checks ensure that the parser
and model raise appropriate assertions rather than failing silently. All unit tests rely on
Python's \texttt{unittest} framework. 

\subsection{Integration Tests}

Integration tests combine parsing, strategy execution and output formatting to
validate end-to-end behaviour.  Such tests are defined in
\texttt{test\_integration.py}.  They construct complete machine definitions,
parse them into model objects and invoke the generator with different strategies
and configuration options.  The resulting Robot Framework text is inspected for
correct structure, coverage annotations and valid keyword sections.

A representative example is the \texttt{test\_parse\_and\_generate\_simple\_machine}
case.  It builds a small machine containing settings and variables, parses it and
runs the generator while tracking which states and actions were visited.  The
snippet below shows the verification of the produced output:
\begin{lstlisting}[language=python]
all_actions = set()
for state in machine.states:
    all_actions.update(state._actions)

generator.generate(
    max_tests=10,
    max_actions=3,
    strategy=DepthFirstSearchStrategy,
    ...
  )

content = output.getvalue()
self.assertIn("*** Settings ***", content)
self.assertIn("TEST COVERAGE INFORMATION", content)
\end{lstlisting}
The test ensures that the pipeline from textual specification to final Robot
Framework file executes without error and that coverage data is embedded in the
output. Coverage counters for states and actions are asserted to appear at the
top of the generated file so that developers can see exactly which parts of the
machine were exercised.

Integration tests are executed using Python's \texttt{unittest}. 

These tests confirm that the system works reliably as a whole and can
handle larger inputs without excessive runtime.

Several scenarios also probe error handling. One integration test feeds the
generator a machine whose rules cannot all be satisfied, verifying that test
generation still completes gracefully. Another constructs a large state machine
containing many variables and branches to observe performance and memory
consumption under stress. 

\subsection{Login FSM Example}

The directory \texttt{generator/example/} provides a complete login state
machine and the Robot Framework tests generated by each strategy based on the FSM in figure~\ref{fig:fsm_example}.  The machine is
specified in the following \texttt{.machine} format:
\begin{lstlisting}[language=,caption={Example FSM defined in .machine format}, label={lst:example_machine}]
*** Variables ***
${VALID_USER}         user1
${INVALID_USER}       invalid_user

*** Machine ***
${USER}       any of    ${VALID_USER}      ${INVALID_USER}

Start
  [Actions]
    authenticate user        ==>  Authenticated    when  ${USER} == ${VALID_USER}
    authenticate user        ==>  Failed           when  ${USER} == ${INVALID_USER}

Authenticated
  [Actions]
    logout                   ==>  Start
  ...
\end{lstlisting}
When processed by the generator, three strategies yield markedly different test
suites. For this generation, we used a maximum of \textbf{5 actions} per test and a limit
of \textbf{5 tests} per strategy. Table~\ref{tab:strategy_comparison} summarizes the key characteristics
and coverage metrics for each approach.

\begin{table}[ht]
\centering
\caption{Comparison of test generation strategies applied to the example FSM}
\label{tab:strategy_comparison}
\begin{tabular}{|l|c|c|c|}
\hline
    \textbf{Strategy} & \textbf{Test Cases} & \textbf{States Covered} & \textbf{Actions Covered} \\
\hline
\texttt{Depth-First} & 5 & 3/6 (50\%) & 5/12 (42\%) \\
\hline
\texttt{Random} & 5 & 6/6 (100\%) & 11/12 (92\%) \\
\hline
\texttt{All-Pairs} & 5 & 6/6 (100\%) & 10/12 (83\%) \\
\hline
\end{tabular}
\end{table}

\textbf{Depth-first search} generates long, deterministic sequences that
systematically explore branches until the maximum action limit is reached, but
may miss unreachable states due to its deterministic nature. With 50\% state
coverage and 42\% action coverage, this strategy shows limited exploration
effectiveness for this particular FSM.

\textbf{Random generation} achieves excellent coverage through stochastic exploration,
visiting all states (100\%) and nearly all actions (92\%) through variability in 
path selection. The high coverage demonstrates the effectiveness of random 
exploration in discovering diverse execution paths.

\textbf{All-pairs} creates the most efficient test suite, achieving complete
state coverage (100\%) and good action coverage (83\%) with only five tests by 
focusing on variable interactions and pairwise combinations. This strategy 
provides an optimal balance between test suite size and coverage effectiveness.

Overall, the example demonstrates how the generator supports different testing
approaches. Depth-first yields systematic but limited exploration, random 
generation maximizes coverage through stochastic variability, and all-pairs 
efficiently covers variable interactions with minimal test cases.

\subsection{Parameter Impact Analysis}
To understand how the \texttt{max\_tests} and \texttt{max\_actions} parameters affect test generation effectiveness, we conducted a systematic analysis across all three strategies. Figure~\ref{fig:coverage_overview} shows the performance comparison and parameter effects.

\begin{figure}[ht]
    \centering
    \includegraphics[width=\linewidth]{coverage_analysis_overview.png}
    \caption{Coverage analysis overview showing strategy performance and parameter effects.}
    \label{fig:coverage_overview}
\end{figure}

The analysis reveals distinct sensitivity patterns for each parameter. Increasing \texttt{max\_tests} has a dramatic impact on the Random strategy, with coverage improving from 67.6\% to 98.5\% as the test limit increases from 10 to 200 tests (Table~\ref{tab:max_tests_effect}). In contrast, the Depth-First strategy shows minimal improvement, plateauing around 74\% coverage regardless of additional tests. This plateau effect occurs because deterministic path-following quickly exhausts unique sequences in finite state machines.

\begin{table}[h!]
\centering
\caption{Effect of Max Tests on Total Coverage (max\_actions=20)}
\label{tab:max_tests_effect}
\begin{tabular}{|c|c|c|}
\hline
\textbf{Max Tests} & \textbf{DepthFirst} & \textbf{Random} \\
\hline
10 & 67.6 & 67.6 \\
\hline
25 & 70.6 & 83.8 \\
\hline
50 & 73.5 & 87.5 \\
\hline
100 & 74.3 & 94.9 \\
\hline
200 & 74.3 & 98.5 \\
\hline
\end{tabular}
\end{table}

The \texttt{max\_actions} parameter shows different patterns (Table~\ref{tab:max_actions_effect}). The Random strategy benefits consistently from longer test sequences, improving from 56.6\% to 91.5\% coverage as sequence length increases from 5 to 30 actions. Surprisingly, the Depth-First strategy exhibits counterintuitive behaviour, with performance decreasing from 83.8\% to 67.6\% as sequence length increases from 5 to 10 actions, then stabilising. This suggests that longer sequences in deterministic exploration may lead to repetitive paths that miss alternative state transitions.

\begin{table}[h!]
\centering
\caption{Effect of Max Actions on Total Coverage (max\_tests=50)}
\label{tab:max_actions_effect}
\begin{tabular}{|c|c|c|}
\hline
\textbf{Max Actions} & \textbf{DepthFirst} & \textbf{Random} \\
\hline
5 & 83.8 & 56.6 \\
\hline
10 & 67.6 & 77.2 \\
\hline
15 & 67.6 & 77.9 \\
\hline
20 & 67.6 & 87.5 \\
\hline
30 & 67.6 & 91.5 \\
\hline
\end{tabular}
\end{table}

Figure~\ref{fig:best_strategy_heatmap} visualises the optimal strategy for each parameter combination, showing that Random dominates at higher parameter values while Depth-First performs best with shorter sequences and higher test counts.

\begin{figure}[ht]
    \centering
    \includegraphics[width=\linewidth]{best_strategy_heatmap.png}
    \caption{Best performing strategy for each parameter combination with achieved coverage percentages.}
    \label{fig:best_strategy_heatmap}
\end{figure}

The analysis provides clear guidance for parameter selection: Random strategy with high \texttt{max\_tests} (100-200) and \texttt{max\_actions} (20-30) achieves optimal coverage but requires more execution time. Depth-First strategy with moderate test counts and short sequences (5-10 actions) offers predictable, consistent results around 75\% coverage, making it suitable for scenarios prioritising reliability over maximum coverage.
